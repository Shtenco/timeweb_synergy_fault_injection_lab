# timeweb_synergy_fault_injection_lab

**SYNERGY / HIAI · Исследование №17: управляемые отказы HTTP-реплик и переключение клиента**

## Исследовательская задача

Проверить, как retry, timeout и failover влияют на успешность запросов и задержки во время остановки локального HTTP-сервера. Стенд содержит две самостоятельные HTTP-реплики и клиента, который при неуспехе может переключаться между ними.

**Статус:** измерения локального эксперимента, но не production-бенчмарк распределённой системы. Название Timeweb в репозитории не означает официального одобрения проекта компанией Timeweb Cloud.

## Экспериментальная гипотеза

Повторы должны повышать долю успешно обслуженных запросов при контролируемых сбоях, но увеличивать число отправок и потенциально ухудшать хвостовую задержку. Для честного сравнения клиент с retry и без retry должен использовать одинаковую последовательность инъекций отказов.

## Подготовленный исходный комплект

- `experiments/fault_injection_lab.py` — реальный локальный стенд.
- `results/17/fault_injection_requests.csv` — данные запросов.
- `results/17/fault_injection_results.json` — агрегированный протокол.
- `article/РУКОПИСЬ.md` — текст исследования.
- `article/HTML_ДЛЯ_ХАБРА.html` — HTML для авторской доработки.
- `article/figures/` — 14 схем и иллюстраций.
- `SOURCE_MANIFEST.json` — контрольные суммы исходников.

**Статус синхронизации:** файлы подготовлены в отдельном исходном комплекте HIAI; наличие каждого из них в GitHub нужно проверять отдельно, README не является утверждением о завершённой загрузке.

## Воспроизведение

Необходим Python 3.10+ и локальное разрешение создавать HTTP-серверы на loopback.

```bash
git clone https://github.com/Shtenco/timeweb_synergy_fault_injection_lab.git
cd timeweb_synergy_fault_injection_lab
python experiments/fault_injection_lab.py
```

Сохраняйте логи прогонов и исходные per-request CSV. Числа из рукописи относятся к конкретной серии локальных испытаний: без retry 91/120, с retry 120/120; дополнительные попытки создают накладные расходы. Это не гарантия для произвольного сетевого окружения.

## Научные ограничения

Стенд **не проверяет** реальные датацентры, межрегиональные задержки, сетевые разделения, TLS, Kubernetes, балансировщики, ошибки DNS или idempotency для небезопасных методов. Для production-вывода необходимы отдельные тесты и статистика.

## Контроль качества

1. Заморозить версию Python, ОС и seed инъекций.
2. Отдельно проверять корректность и хвостовые latency P95/P99.
3. Включить negative-control без сбоев.
4. Запустить независимые повторы и сохранить сырые данные.
5. Сверить выводы статьи с полными JSON/CSV протоколами.
6. Указать источники внешних утверждений, лицензии и правила Timeweb Cloud.

## Публикационные требования

Рукопись является редакционной основой. Для согласования с Timeweb Cloud требуется самостоятельный авторский текст, достоверные иллюстрации, методика, ограничения, итог и честные ссылки на исходники. Лицензия исходного проекта пока не определена.
